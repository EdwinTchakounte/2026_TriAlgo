# =============================================================
# FICHIER : requirements.lock.txt
# ROLE    : Versions EXACTES des dependances installees dans l'image
# =============================================================
#
# pyproject.toml DECLARE les dependances (avec des bornes basses).
# Ce fichier FIGE les versions effectivement installees. Le
# Dockerfile n'installe que lui.
#
# POURQUOI
# --------
# L'image recalculait toutes les versions a chaque build
# (`pip-compile` sur pyproject.toml). Deux defauts :
#   - deux builds a une semaine d'intervalle n'installaient pas le
#     meme code : une mise a jour amont pouvait casser la prod sans
#     qu'une ligne du depot ait change ;
#   - le 2026-10-18, la resolution ne terminait plus (99 % CPU
#     pendant plus de dix minutes, sur le serveur comme en local).
#     Le deploiement etait bloque par un calcul, pas par le code.
#
# Ces versions sont celles de l'image qui tournait en production
# depuis cinq semaines (pip freeze du conteneur api) : eprouvees.
#
# METTRE A JOUR, volontairement
# -----------------------------
#   pip install pip-tools
#   pip-compile --upgrade --output-file requirements.lock.txt pyproject.toml
# puis reconstruire, tester, et commiter ce fichier.
# =============================================================
